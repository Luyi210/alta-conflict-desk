# 工具调用台

工具调用台供律师在案件核查前验证数据源能力，或在来源失败时定位问题。目录、参数定义、执行状态与结果均来自后端；页面不生成模拟成功结果。此页面由用户手动发起，不能作为「真实 AI 已调用」的证明。案件中的模型模式仍需要另行配置模型 API。

## 操作流程

1. 在「接入管理」连接 GLEIF 或本地律所台账。连接器通过 MCP `tools/list` 发现工具与输入 schema；首次未连接时不显示虚构工具目录。
2. 进入「工具调用台」，从左侧选择查询能力。可查看中文用途、来源与启用状态；「技术参数与 MCP 定义」可展开服务实际返回的说明和 schema。
3. 填写查询条件。表单按实际 schema 生成；可切换 JSON 参数。客户端检查 JSON 对象、必填字段及基本格式，后端校验完整 schema。
4. 可点「填入 HSBC 公开企业示例」。这只填写查询参数，不生成返回数据。使用的 `HSBC BANK PLC` 示例 LEI 为 `MP6I5ZYZBEU3UXPYFY54`。
5. 点「执行查询」。服务异步创建调用记录，页面轮询该记录的实际状态。执行中防止重复提交；离开页面后请求仍可能继续，返回页面会恢复展示和轮询。
6. 调用完成后点「查看参数与原始结果」，通过现有追踪抽屉查看输入、结果、来源及耗时。调用成功仅说明工具返回数据，不表示完成法律判断。
7. 失败调用保留原始错误。点「使用原参数重试」会创建新记录，并保留 `retryOf` 与原调用的关联，不覆盖原失败记录。

## 接入、权限与数据范围

- 每项工具可独立启用或暂停。设置由后端持久化，并适用于后续手动、规则及模型调用；已经发起的只读请求不会因此被取消。
- 来源断开后可以展示上次发现的参数，实际调用会被禁止。通过「去连接」返回接入管理；重新连接后可刷新目录。
- GLEIF 查询会把输入名称或 LEI 发送至其公开服务，仅覆盖已登记 LEI 的主体。母公司关系指会计合并母公司，不代表完整持股、受益所有人或全部关联关系。
- 律所台账为本机隔离、只读的虚构数据，不代表真实客户委托关系。
- 工具调用台历史只列手动测试记录。规则/AI 核查的工具追踪在对应核查详情中查看。
- 网络中断导致状态暂不可读时，页面不会将调用伪装成失败或成功，也不会自动重发查询。

## 前端接入

`src/ToolDesk.tsx` 的默认组件接受 `onError(message)`、`onTrace(trace)`、`onConnections()` 三个回调，分别复用全局提示、原始追踪抽屉和连接器导航。组件自带 `src/tool-desk.css`，不引入新依赖。

使用 `/api/tool-desk` 的目录、权限、创建调用、轮询、重试接口，完整端点约定见 [V2-CONTRACT.md](./V2-CONTRACT.md)。表单字段来自实际 schema，中文名称仅用于解释已发现工具，不会创建或补造工具。
