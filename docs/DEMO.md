# v0.2 核心流程演示脚本

现有 [80 秒截图演示草稿](demo-walkthrough.mp4)及 [字幕](demo-walkthrough.srt)仅展示 **v0.1 单主体规则流程**。九张源截图为 `screenshots/01-workspace.jpg` 至 `screenshots/09-history.jpg`。它不是连续录屏，没有配音或真实模型调用，**不代表 v0.2 案件、补证、总意见或工具台已被视频覆盖**。

旧视频可用 `python3 scripts/render-demo.py` 重建，需要已安装的 Pillow、FFmpeg 和中文字体；脚本不会安装系统包。`demo-walkthrough.json` 记录源截图哈希及媒体信息。重新渲染旧素材不会产生 v0.2 演示证据。

以下为新版连续操作录制脚本。以实际界面和当次响应为准，不剪接出不存在的成功。当前没有模型 API 实跑证据；完整 AI 版本需要先获得接口、验证真实工具调用，再录制。

## 演示前准备

1. 按 README 启动，打开 <http://127.0.0.1:5178>。确认 GLEIF 外网可访问，两个 MCP 连接器可连接。
2. 确认本次运行方式。没有模型 API 时，画面和旁白均明确“规则预览 / 手动测试”。
3. 检查工具是否启用，准备一条虚构事项；不录制 `.env`、终端密钥、登录信息或含密码的聊天记录。
4. 已有记录明确为准备阶段记录。要证明复现，应新建案件或新发起一次实际工具调用。
5. 按最新 [浏览器验收记录](BROWSER-VERIFICATION.md)检查可用状态；本脚本描述拟录顺序，不是已经录制的证明。

## 建议时长：5–7 分钟

| 时间      | 操作                                                                         | 解说要点                                                                                  |
| --------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 0:00–0:25 | 展示案件工作台与场景                                                         | “律师收案前需要确认各方身份，并看到哪些材料和关系尚未核实。”                              |
| 0:25–1:00 | 在接入管理连接 GLEIF 与台账，测试连接并展开工具                              | “两个 MCP 服务真实运行。公开信息实时查询，内部台账委托关系明确为虚构。”                   |
| 1:00–1:45 | 打开工具调用台，选择查找企业身份，填 HSBC 示例并执行，展开追踪               | “参数定义来自实际 MCP；示例只填入查询条件。这里能看见本次参数、状态、原始结果及耗时。”    |
| 1:45–2:45 | 回案件工作台，填入演示事项，分别确认交易对方和担保方，保留拟委托人身份未确认 | “最多六个企业，各方已确认后分别核查；缺少身份不会被静默跳过。”                            |
| 2:45–3:40 | 发起规则核查，展示按主体进度、线索及真实调用                                 | “已确认的各方进入同一套工具流程；公开母公司是会计合并口径，不自动等于法律冲突。”          |
| 3:40–4:40 | 查看补证清单，展示跨主体合并项，填写一项演示核实说明与材料引用文本           | “身份/来源缺口由系统管理，不能勾选消除。人工补证保存说明与引用，不代表已上传或核验文件。” |
| 4:40–5:25 | 记录案件总意见为待补充材料；展示阻塞项和不可标记完备                         | “未确认拟委托人仍在案件范围内。总意见可记录待补状态，但系统不会给出自动通过。”            |

如要压缩到五分钟，可缩短输入并保留一个补证及一个变更示例。不要为了展示“完备”而无依据地把全部线索排除。

## 演示输入与数据说明

使用页面“填入演示事项”可准备：

- 事项：`澄川科技 · 跨境融资收案审查（虚构）`。
- 拟委托人：`澄川科技有限公司（虚构）`，保留未确认身份，用于展示阻塞和补证。
- 交易对方：查询 `MP6I5ZYZBEU3UXPYFY54`，核对当次 GLEIF 返回的 `HSBC BANK PLC` 后确认。
- 担保方：查询 `21380081EP12LC86CB82`，核对当次返回的 `HSBC UK BANK PLC` 后确认。
- 辖区：仅为事项背景，不代表系统已经应用该辖区的职业规范。

公开名称与 LEI 可以真实；所模拟融资、交易角色、律所委托、事项与经办人均虚构，不能推断真实交易或委托关系。虚构拟委托人没有可确认身份时应继续保留待补状态，不能随意替换成别家真实公司的 LEI 来消除阻塞。

补证说明可示范填写“演示：已核对虚构事项委托范围摘要，仍需负责律师确认相关性”；材料引用可填写“演示材料 A，第 2 节（仅引用文本，未上传）”。如果内容仍未核实，应保留待补状态，不标成已完成。

若要演示身份补录，可另建一个所有角色均明确为模拟的案件，先保留一个**已知真实登记名称但尚未确认**的主体，后续从真实候选中核实并确认。不要将虚构公司和真实公司视为同一主体。公开 API 可能更新或暂时不可用，不预先承诺线索数量、母公司名称或耗时。

## 工具权限与失败分支

选择一个短分支补充主流程即可，避免把所有异常塞进同一视频：

1. **暂停工具**：在工具台关闭一项工具，展示执行按钮限制，并在下一次依赖该工具的核查中观察后端拒绝或来源缺口。说明统一权限约束手动、规则及模型；恢复后再运行。已发起请求不会被假称取消。
2. **来源断开**：断开连接器，工具台保留上次发现的定义但显示不可用，引导重新连接。首次未连接时不显示虚构工具。
3. **无效参数**：在 JSON 模式填写格式错误或缺少必填值，显示校验提示；参数校验失败不是成功工具调用。
4. **实际调用失败后重试**：仅在真实失败已发生时展示原错误和“使用原参数重试”，确认新记录的 `retryOf`。没有失败记录就不伪造故障或成功截图。
5. **身份未确认**：保留一个主体未确认，展示覆盖计数、补证和总意见阻塞；不能通过普通完成勾选消除身份缺口。

## 必须拍到的验收证据

- MCP 连接、工具发现、至少一条实际调用、输入、返回与耗时。
- 工具台 schema 与权限确实影响后续执行，成功状态来自后端。
- 案件包含多个角色，已确认与未确认身份的覆盖清楚区分。
- 公开信息与虚构内部事项明确标注；母公司口径与覆盖限制可见。
- 补证说明、引用文本与人工复核保存后可重新查看。
- 阻塞项禁止标记完备，证据变化使旧总意见失效并保留活动。
- 导出报告体现案件各方、缺口、人工判断与工具来源。
- 没有模型时，规则与手动调用不描述成“AI 自主调用”。

完整题目还须额外拍到：**模型实际发出工具调用 → MCP 执行 → 模型使用真实返回与引用**。模型配置存在和 mock 测试都不能替代该证据。
