# 核心流程演示脚本

当前已有 [80 秒截图演示草稿](demo-walkthrough.mp4)，它串联的是本次浏览器实际操作截图，带章节说明、长页纵向平移和 [中文字幕](demo-walkthrough.srt)。**它不是连续录屏，没有配音，也没有模型实际调用。** 开场、片尾及画面固定标识都说明这一边界。

九张原始截图位于 `screenshots/01-workspace.jpg` 至 `screenshots/09-history.jpg`。浏览器已实际验证两组 MCP 连接、GLEIF 连接测试、5 个候选中的主体确认、4 次规则调用与 3 条线索、关联证据、近似名排除理由、报告下载以及历史记录。截图视频展示结果状态，不模拟点击过程，也不提供真实耗时证据。

视频可用 `python3 scripts/render-demo.py` 重建；需要已安装的 Pillow、FFmpeg 和中文字体，脚本不会安装系统包。`demo-walkthrough.json` 记录源截图哈希与 ffprobe 媒体信息。

下文为最终连续操作视频的录制脚本。请使用实际运行界面与实际接口响应；不要剪接出不存在的成功结果。完整 AI 版本仍须获得模型 API 并实际验证后再录制。

## 演示前准备

1. 按 README 启动项目，打开 <http://127.0.0.1:5178>，确认前端和后端可访问。
2. 确认两个 MCP 连接器均可连接，GLEIF 外网可访问。
3. 确认当前演示运行方式：没有模型 API 就说明“规则预览”；有模型则先完成真实工具调用验证。
4. 不录制 `.env`、终端密钥、浏览器保存的登录信息或含密码的聊天记录。
5. 若录屏开始前已经有运行记录，说明它们是准备阶段记录；要展示可复现性时重新创建一次核查。

## 建议时长：3–5 分钟

| 时间 | 操作 | 解说要点 |
| --- | --- | --- |
| 0:00–0:25 | 展示工具台入口和场景 | “这是一位律师接受新委托前，确认对方企业并核查本所关系的工具台。” |
| 0:25–1:00 | 连接 GLEIF 与示例台账，测试并查看工具 | “公开信息实时查询；内部事项是明确标记的虚构数据，但查询通过真实 MCP 和 SQLite 执行。” |
| 1:00–1:40 | 新建事项，搜索 `HSBC BANK PLC`，核对候选并确认 | “名称相近的企业不能直接当作同一主体，先确认法律名称、地区和 LEI。” |
| 1:40–2:30 | 启动核查，展示进度及 MCP 调用记录 | “这里能看到实际工具、参数、耗时、结果与错误。当前运行方式以页面标识为准。” |
| 2:30–3:30 | 查看一个命中及其来源，记录复核判断 | “命中是一条待判断线索；公开上级关系不自动等于法律冲突。律师保留复核理由。” |
| 3:30–4:10 | 导出报告，查看范围、来源和人工复核 | “结果带有核查时点和覆盖缺口，方便后续合伙人复核与归档。” |
| 4:10–4:40 | 演示一次断开或失败分支 | “来源不可用时不会显示全面通过，也不会把预设数据当成实时结果。” |

## 示例输入

- 事项：`澄川科技 · 跨境融资项目`
- 拟委托人：`澄川科技有限公司（虚构）`
- 核查对象：`HSBC BANK PLC`
- 企业 LEI：`MP6I5ZYZBEU3UXPYFY54`
- 对象角色：按界面选择或填写本次事项中的对方角色。

公司名称与 LEI 来源于公开身份记录。示例中与律所之间的客户关系、委托事项、经办人等均为虚构，不能据此推断任何真实律师事务所或公司之间的委托关系。

演示不要预先承诺具体父公司名称、线索数量或网络耗时。公开 API 可能更新，也可能暂时不可用，应以当次响应为准。

## 必须拍到的验收证据

- 连接器确实可以连接、测试、断开；工具列表来源于真实 MCP 发现。
- 用户从候选列表确认主体，而非只提交一个模糊名称。
- 至少一条实际 MCP 调用及对应结果、来源和时间。
- 公开身份/关系数据与虚构内部委托数据有清晰标注。
- 复核理由保存后仍可在记录或报告中查看。
- 没有模型时，画面与旁白均注明规则预览。
- 满足完整题目时，额外拍到模型真实发起工具调用的运行记录；规则预览录屏不能替代这一证据。

## 异常分支

任选一个短分支即可，不需要把所有错误都塞进主视频：

1. **未连接**：断开台账后重新发起，展示拒绝执行或明确缺失来源。
2. **候选歧义**：搜索较宽泛名称，说明需要用户确认正确实体。
3. **公开服务异常**：真实请求失败时展示错误；不要人为伪造第三方故障截图。
4. **线索排除**：用名称近似线索演示排除理由，避免将“没有完全相同名称”作为法律结论。

建议最终连续录屏文件名 `core-flow.mp4`，与现有的 `demo-walkthrough.mp4` 截图草稿分开保存。若视频仅验证 UI 与 MCP，应在 GitHub 提交说明中明确模型实跑仍待补充。
