## 最小验收流程

1. 从干净目录获取代码，使用 Node 24 执行 `npm ci`。
2. 按 README 启动；不依赖作者机器上的未声明服务。
3. 连接两个 MCP 服务，确认工具列表来自实际发现。
4. 搜索并确认主体，成功完成一次规则核查。
5. 展开线索，核对公开来源、内部虚构记录与实际调用记录。
6. 保存一次人工复核，刷新后确认保留，导出报告。
7. 断开来源后执行受影响操作，确认系统不显示虚假的全面通过。
8. 配置模型后完成一次模型工具调用运行，保留可核验记录。
9. 按真实操作录制视频，将代码、说明、研究与沟通记录提交 GitHub。

## 提交前检查

- [x] README 中端口、命令、环境变量与实现一致。
- [x] 锁文件纳入仓库，`.env`、运行数据库和日志未纳入仓库。
- [x] 没有测试账户密码、模型 key 或其他凭证。
- [x] 虚构台账在界面、报告和 README 中都有标识。
- [x] 不将名称相似、公司关联或“未命中”描述为确定法律结论。
- [x] 模型未实跑的缺口没有被隐藏或写成已完成。
- [x] 开源复用范围和许可证明确，代码依赖与设计参考分开。
- [ ] 视频显示真实调用、人工复核与导出，不只展示静态页面。
