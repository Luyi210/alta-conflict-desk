# v0.4 产品体验与验收

日期：2026-10-30。目标用户仍是律所负责收案初查的律师或助理。本轮围绕已有收案审查，把“打开后做什么、离开后如何继续、当前还缺什么”串成完整路径，没有扩大到通用法律平台。

## 入口与路径

| 页面 | 解决的问题 | 实现 |
| --- | --- | --- |
| 收案工作台 | 新建入口和历史记录分散，不知道先处理什么 | 真实案件统计、最近待办、核查环境、案件搜索、状态筛选、时间排序 |
| 三步新建 | 长表单同时呈现背景、身份和执行配置，顺序不清楚 | 事项信息 → 确认相关方 → 核查确认；每步校验后继续，示例仅填表 |
| 案件页 | 取证完成容易被误认为全部审查完成 | 身份确认、证据核查、补证与复核、记录总意见四阶段；显示实际工具调用数及下一步 |
| 继续工作 | 刷新或去管理连接后容易丢失上下文 | hash 深链接保存案件、核查与标签页；新建草稿存入 sessionStorage |
| 使用指南 | 用户首先遇到技术与作业说明 | 操作步骤和常见问题在前；集成与开源资料放入折叠区 |

首页统计来自当前案件 API。已结束及记录完备的审查不计入待办，历史核查轮次不重复累计；正在核查时自动更新。搜索匹配事项名称、相关方名称、LEI 或案件编号。列表搜索和筛选为当前视图状态，重新进入页面会重置。

新建最多六方，至少一方确认后才能启动；未确认方明确保留为缺口。确认页说明发送到配置模型的数据范围。草稿仅保存在当前浏览器标签页，不进行服务器同步，创建成功后清除；关闭标签页后不保证恢复。损坏或结构不合法的暂存内容不会被恢复为已确认身份。

## 真实验证

- 自动测试：48 / 48 通过。新增深链接解析与草稿恢复边界测试，其余包括 MCP 权限、模型范围与引用校验等既有测试；测试不替代真实外部实跑。
- `npm run build`：TypeScript 和生产构建通过。
- 浏览器：搜索无结果和清除、已结束筛选、离开向导查看连接器再返回并刷新恢复、两个真实身份查询与确认、三步创建、运行进度、补证标签页刷新恢复、主体详情刷新与返回父案件、报告实际下载、创建成功后草稿清空、使用指南折叠交互。
- 390 × 844：工作台与新建首步 `scrollWidth === clientWidth === 390`。发现表格内无定位祖先的无障碍文本引发整页溢出，已通过定位滚动容器修复。宽表格仅在内部滚动。验收后恢复默认视口；本轮未声称覆盖所有手机步骤或辅助技术。
- 浏览器检查未捕获 error / warn。截图：[工作台](screenshots/v4-dashboard.png)、[新建](screenshots/v4-intake.png)、[案件](screenshots/v4-case.png)、[移动工作台](screenshots/v4-mobile.png)。

## 实现与取舍

使用既有 React、Zod、Lucide 和 CSS，没有增加路由框架或设计组件库。界面沿用绿色、白色、衬线标题与细分隔线，统计和状态均来自真实记录。使用 frontend-design 技能辅助设计与实现；未复制 Alta Lex 源码、图片或组件。

未来集成时，工作台和新建向导可作为 Alta Lex 的案件插件入口，复用宿主身份、权限与案件编号；当前 hash 导航和单机草稿替换为宿主路由及受控草稿存储。后端 MCP 白名单、工具权限、来源回执与人工复核边界保留；多租户、真实律所台账、文件权限与审计身份需要另行实现。本版仍是本机单用户原型，未扩大这些能力声明。

按用户优先功能的要求，本轮未制作视频；连续演示与私有仓库评审访问仍是最终交付后续项。
