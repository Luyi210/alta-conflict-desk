# v0.3 产品化审查与实现说明

2026-10-30。定位：可在本机独立运行、可供演示与试用评估的收案审查原型。本轮围绕律师处理路径、证据可信度和操作连续性改进，没有扩展成通用法律平台。

## 真实使用问题与本轮改动

| 问题 | 实现 | 验收原则 |
| --- | --- | --- |
| “进一步复核”被显示为已处理，子页待办数与案件汇总不一致 | 四种线索状态：待复核、进一步复核、已复核保留问题、已排除；筛选后详情同步 | 前两种仍阻塞完备状态；保留问题要求说明，不表示批准收案 |
| 律师只能排除全部线索才能结束流程 | 增加保留问题，以及“不承接、结束审查”结局 | 不承接可以保留身份、材料和复核缺口；运行中的核查不可结案；新证据使旧意见失效 |
| 背景字段没有进入模型 | 委托背景、拟委托人和辖区传至每个主体核查及模型请求 | 辖区仅作背景，不自动推导法律适用；仍仅允许查授权主体与已知母公司 |
| AI 长段摘要难核对，存在真实引用对应错误描述的情况 | 工具返回直接生成“来源记录”；AI 分别生成待核实问题与建议动作；摘要明确待律师核对 | 不以模型生成的 facts 作为事实卡；母公司须逐一实际查台账并引用，缺少则要求补查；每条来源可打开原始返回 |
| 材料写到一半无法保存，切换页面丢失输入 | 补证支持保存草稿和独立完成；意见、补证、线索说明均在当前标签页暂存；明确已保存/未提交 | 显式保存进入 SQLite；临时输入在 sessionStorage，仅保证同标签页切换/刷新，关闭标签页后不承诺恢复 |
| 新证据使旧意见文字消失 | 状态恢复草稿，意见文字和填写人保留；保留失效活动记录 | 不把旧意见继续视为有效；保存补证/总意见附带当前 revision，过期版本拒绝覆盖 |
| 不易判断下一步 | 案件顶部增加下一步入口；补证显示涉及的具体主体；主体允许更正并生成新核查 | 历史核查保留，更正会使旧总意见失效 |

## 实测中发现并修复的来源问题

本轮第一条实跑 `0ef2be6a-bded-4385-a4b4-ddf38a8e8ef1` 完成了 3 次模型 MCP 调用，但模型将预核查中母公司的精确匹配描述为该次子公司台账查询的返回。该调用确实存在，其结果却不支持这段描述。这证明仅校验 trace ID 存在是不够的。

因此采用两层输出：来源卡由结构化工具数据生成，文字不经模型重写；AI 摘要和建议明确待律师核对。模型要完成流程，还必须分别调用并引用所选主体及每个已知母公司的台账结果。原始首轮记录保留，不把它伪装成修复后的验收。第二轮 `175f14ad-11b5-4281-bf47-60d5bb6f4764` 暴露模型批量请求超过原先每轮 4 次限制的问题，正确保留规则结果为 partial。将每轮合理批量上限调整为 6，全程 12 次、6 轮与主体白名单不变，避免对少量已授权主体的正常查询误判。新的运行与浏览器结果另见本页后续验收记录。

这一措施减少“事实卡”的生成性错误，但不声称自动证明 AI 全部文字真实或判断法律相关性；摘要与建议仍须人工复核。

## 技术与兼容取舍

- 复用现有 React、Express、MCP SDK、SQLite 和样式系统，无新增第三方依赖。
- 新字段为可选，既有本机记录保持可读；旧模型文字不被改写为新版输出。
- 原始工具凭证保持完整；来源卡只提取名称、LEI、关系类型、事项及匹配类型。
- 当前仍仅覆盖 LEI 企业身份；没有登记身份的主体保持缺口。人工可记录不承接，不得用勾选绕过身份核查。
- 原型中人工复核身份未认证、补证材料为引用文本；未接入真实律所台账、文件系统、审批或消息系统。

## 走向实际产品的后续门槛

正式多用户部署需先接入 Alta Lex 的组织身份、事项权限和可验证复核人，再接真实台账及文件引用，增加备份恢复、访问审计和面向实际资料的模型评测。完成真实组织小范围试用后，再评估公开发布。当前的“产品化”指本地体验与流程质量，不等于已经具备商业上线条件。
