| 搜索资料 | 围绕同一主张主动寻找反证，展示检索范围 |
| 生成分析结果 | 区分“有材料支持、存在疑似冲突、证据不足、待律师确认” |
| 单次分析 | 加入新证据后，标出哪些判断发生变化及原因 |

最终交付物是一个**争点与证据矩阵**：

> 对方主张 → 支持材料 → 相反材料 → 尚缺材料 → 律师复核意见。

它很适合这道题的工具台要求：律师需要选择允许检索的文件夹、邮件范围，查看工具调用及资料来源；连接失效或访问受限时，界面要清楚显示哪些材料尚未检查。

**两天原型可以收窄到一个商事付款争议、三个争点、十份左右测试材料。** 先跑通云盘资料读取和原文核验，邮件连接作为加分项。分析围绕律师给定的争点展开，结论保留人工复核。

**2．对方文书的“引用与论证核验”——法律专业辨识度很高**

具体场景：律师拿到对方的法律意见或诉讼文书，检查里面引用的案例，以及案例是否真的支持对方的论点。

可以参考：

- **[eyecite](https://github.com/freelawproject/eyecite)**：提取美国法律文书中的案例引用、短引及引用位置。
- **[CourtListener](https://github.com/freelawproject/courtlistener)**：开源法律数据平台；其[引用查询 API](https://www.courtlistener.com/help/api/rest/v4/citation-lookup/)可以查找引用并返回匹配或歧义情况。

增强可以分三层：

| 层次 | 核查内容 |
|---|---|
| **引用核验** | 能否找到对应案件，名称和引注是否匹配 |
| **引文核验** | 文书中的引文与裁判原文是否一致，是否遗漏相关上下文 |
| **论证核验** | 原文对该论点是支持、部分支持，还是关联不足，并提供依据供律师判断 |

亮点可以设计成：

> 点击对方的一个论点，同时看到引用、裁判原文和 AI 的核验理由；律师确认后，加入回应提纲。

技术上需要将 CourtListener 查询和取原文能力封装为 MCP 工具。**首版适合限定美国判例**，并把检索不到的结果标为“未能核验”；数据库中没有匹配结果，不能直接证明案例虚构。

这个方向比普通法律检索更像律师的审查工作，但账号权限、接口限流和数据覆盖需要先验证。

1. 律师提出需要核查的具体事实，选择目标网页。
