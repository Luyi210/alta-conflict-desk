# AI 协作决策记录（脱敏摘要）

本文件记录原型制作中的主要讨论、判断与分工，便于评审理解 AI 使用范围。它是整理后的决策摘要，**不是原始聊天逐字导出**。未包含账号密码、密钥或其他不宜提交到仓库的信息。

整理日期：2026-10-27。当前方案对应 v0.2 案件工作台与工具调用台。

## v0.2 的具体分工

- 主实现负责案件前端、路由接线、功能集成与浏览器验证。
- 案件模块负责多主体编排、派生补证、覆盖缺口、总意见失效、持久化与报告。
- 工具引擎负责真实工具发现 schema、统一权限、异步调用记录、失败重试与模型调用限制。
- 工具 UI 负责动态表单/JSON、权限开关、状态轮询、错误与追踪入口，并补充使用说明。

共享合约见 [V2-CONTRACT.md](V2-CONTRACT.md)。并行实现按文件职责隔离，之后由主实现整合。自动测试、浏览器验证和真实模型验证分别记账，不能互相替代。

## AI 参与的工作

- 梳理律师场景、工作流、边界和实现取舍。
- 检索和阅读官方项目资料，核实热度、许可证与可参考范围。
- 生成并迭代前后端、MCP 适配、虚构台账、持久化与验证脚本。
- 检查“身份匹配”“潜在线索”“材料齐备”“允许收案”是否混淆。
- 检查权限是否同时作用于手动、规则及模型调用，而不只是 UI 开关。
- 编写启动、研究、使用、演示与集成说明。

业务代码由本次协作实现。第三方依赖与设计参考见 [RESEARCH.md](RESEARCH.md) 和 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)；阅读过开源项目不等于完整复用其源码。

## 关键约束与选择

1. **真实数据调用**：公开查询必须经过 MCP；外网失败不以静态结果冒充成功。工具台示例仅填参数。
2. **各方身份与范围**：拟委托人与交易对方等均可核查。已确认者进入查询；未确认者保留为缺口，不能在汇总中当作通过。
3. **内外数据分别说明**：公开公司身份可以真实；律所委托、内部事项与演示角色均虚构。
4. **规则、手动与模型区分**：模型 API 尚未实跑。适配器、配置状态和 mock 协议测试都不是 AI 验收证据。
5. **职业判断留给律师**：精确身份或关联企业命中只是线索；“审查记录完备”也不是批准收案。
6. **补证有实际保存边界**：保存核实说明与材料引用文本，未实现文件上传、真实性验证或真实合伙人通知。
7. **意见随证据失效**：身份、补证、重跑或子核查结果/复核变化会恢复总意见为草稿，保留修订和活动记录。
8. **工具权限统一执行**：启停设置必须由后端约束后续手动、规则与模型调用；不能只把按钮变灰，也不能假称取消已发起请求。

## 验证与待完成事项

“代码已实现”“测试通过”“浏览器验证”“模型实跑”“视频录制”“上传 GitHub”是不同状态。最新证据以 [DELIVERY-CHECKLIST.md](DELIVERY-CHECKLIST.md) 与 [BROWSER-VERIFICATION.md](BROWSER-VERIFICATION.md) 为准；本摘要不推定全部完成，也不固定可能过时的测试数量。

制作期间，GitHub CLI 曾在网络受限环境报告登录失败。进一步核验后确认凭据可用，创建了私有交付仓库。普通 Git 传输随后超时，改用 GitHub 官方 Git 数据 API 上传并核对远端文件树；不将初步误报描述为账号失效。各版本是否已同步，以最新交付记录为准。

模型适配测试使用 mock 验证协议和限制，不等于真实模型调用。现有 `demo-walkthrough.mp4` 仅为 **v0.1 单主体规则流程的截图草稿**，不是连续录屏，也不覆盖 v0.2 案件与工具台。

若评审要求原始 AI 沟通记录，应另行从对话导出、人工脱敏并删去登录凭证后交付；不要把包含测试账号密码的完整对话直接上传仓库。
